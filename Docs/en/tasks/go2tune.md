# Go2Tune

## Overview

A single Task contains everything needed to run one automated agent experiment. The system does not depend on any code outside its own folder — all required code is collected into the Task directory before execution.

The core of a Task folder is the schedular. It orchestrates the agent and integrates agent-environment information, ensuring the agent can access what it needs during execution and complete its attempts in the environment as intended.

## Implementation

### Defining Goals

Go2Tune's goals are declared in the schedular as metric thresholds and passed into the agent as parameters:

- `mean_lin_vel_error <= 0.25`: error between the robot's actual velocity and the commanded velocity
- `fall_rate <= 0.2`: fraction of evaluation episodes ending in a fall

The schedular is only responsible for declaring these thresholds. Whether the goal is met is determined automatically by the agent's internal `goal_met` function after each trial, and the result is recorded in the final report.

### Component Assembly

The schedular performs a one-time path resolution and component initialization at startup, then injects the full context into the agent. It takes no further part in the training process. Specifically:

- Creates the run directory and subdirectories (`agent_memory/`, `training_runs/`, `logs/`) under `Runs/` using the current timestamp
- Resolves absolute paths for all Task-internal components (`Agents/PPOTuner`, `Envs/Go2Locomotion-PPO`, `Agents/CurveAnalyst`) and passes them to `TuningAgent` as `env_path`, `harness_path`, etc.
- Loads agent configuration (model name, etc.) from `Agents/PPOTuner/config.json`
- Registers the `on_trial_done` callback: after each trial, the schedular passes the trial's `curve.png` to `CurveAnalyst` for visual analysis and injects the returned text into the agent's main loop as a supplementary observation

### Output Collection

Each run produces the following structure under `Runs/<timestamp>/`:

```
Runs/
└── 20261003_171150/
    ├── summary.json              # full session summary (success, best trial, elapsed time, etc.)
    ├── agent_memory/
    │   └── longterm.json         # agent long-term memory, written by the reflection mechanism after each trial
    ├── logs/
    └── training_runs/
        └── trial_001/
            ├── config.json       # normalized hyperparameters used for this trial, written by the training function
            ├── summary.json      # training result metrics, written by the training function and returned to the agent
            ├── metrics.csv       # full training log written incrementally by the training callback
            ├── policy.zip        # saved policy weights, written by SB3 after training completes
            └── curve.png         # training reward curve, generated by the visualization module after training
```

`summary.json` at the run root is written by the schedular after the agent exits, summarizing the global results of the session.
