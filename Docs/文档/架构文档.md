# 架构文档 — AutoSimulationTrainingAgent (ASTA)

## 1. 总体思路

智能体的任务是**黑盒配置优化**：每做一次实验（trial）= 用一组超参训练一个 PPO 策略，
观察指标后决定下一组配置。搜索空间维度不高但反馈噪声大、单次实验成本高，
因此需要「推理 + 行动」交替、把失败转成先验、并严格约束预算。

| 技术 | 是否采用 | 理由 |
|---|---|---|
| **ReAct** | 采用（核心） | 调参本质是「分析当前证据 → 决定下一个实验 → 观察结果」的闭环，Thought/Action/Observation 与之天然同构。 |
| **Tool Use** | 采用（核心） | 训练与评估是真实的、耗时的、可能失败的外部动作，必须以工具形式调用。用 DeepSeek function calling，失败时回退到 JSON 解析。 |
| **Memory** | 采用 | 短期记忆保存本次会话的 trial 轨迹（进上下文）；长期记忆跨会话持久化「教训」，避免重复试错。 |
| **Reflection** | 采用 | 每个 trial 后用独立 LLM 调用诊断「为何成功/失败」并抽取一条可复用教训。 |
| **Harness** | 采用 | 用 `Harness/exec.py` 隔离 Agent 与 Env——Agent 不直接 import Env 代码，只通过 Harness 调用。 |
| **RAG** | 不采用 | 没有外部语料库；「知识」来自实验反馈本身（Memory 已覆盖）。 |
| **Multi-Agent** | 未采用 | 单智能体 + 工具已能覆盖任务；后续可以「独立 Critic」形式增量引入。 |

**一句话**：`deepseek-reasoner` 作为推理内核，套一个 **ReAct Harness**，通过 **工具层** 操作真实训练环境，
用 **双层记忆 + 反思** 累积经验，在 **预算** 内完成多轮自动调参。

## 4. 数据流（一次 trial）

1. LLM 输出 `run_training(config, timesteps, seed)`。
2. `config.normalize()` 对配置做校验 + 越界裁剪 + 结构修正，返回 warnings。
3. Harness 调用 `train_ppo.train()`，落盘 `config.json / metrics.csv / policy.zip / summary.json`；
   训练结束后产出 `rollout.mp4`（无 OpenCV 退化为 `rollout.gif`）与 `curve.png`。
4. 工具把 `summary`（mean_return / fall_rate / mean_lin_vel_error / convergence_delta）回传为 Observation。
5. `CurveAnalyst` 分析 `curve.png`，返回文字趋势描述，附加进 Observation。
6. `reflection.reflect_on_trial()` 诊断该 trial，产出 `Lesson` 写入长期记忆。
7. 短期记忆追加 `TrialRecord`；上下文被 `_cap_context` 裁剪到上限。
8. Harness 检查预算与 `goal_met`；未达标则回到步骤 1，否则等待 `finish` 或预算耗尽。

## 5. 关键设计决策

### 5.1 成功判定与模型自评解耦

`goal_met()` 用 best trial 的客观指标判定成功。判据是**存在的键的子集**：
`mean_lin_vel_error_max` / `fall_rate_max` / `mean_return_min` 中出现的键都必须满足，
缺席的键忽略。当前任务以 `mean_lin_vel_error`（= mean(|vx − vx*|)）+ `fall_rate` 评分：
站定 ≈1.0、按命令速度走 ≈0。同时记录 `llm_finished_success`，评测只信客观判据。

### 5.2 固定奖励护栏（reward pinning）

若把奖励权重也交给智能体，它会倾向于改写计分函数而非真正调好超参——各 trial 的
return 便不可比。因此 `ToolContext.fixed_reward` 在 `run_training` 内强制覆盖智能体传入的
`env.reward` 并回一条 warning。智能体只能在 PPO 超参、PD 参数与 `timesteps` 上优化。

### 5.3 timesteps 作为自由超参

早期版本把 `timesteps` 钉死在任务预算。经确认，**训练步数本身是可接受的调参维度**，
遂撤销钳制：`spec.timesteps` 为 `[10000, 2000000]`，智能体可按需延长单轮训练。

### 5.4 工具即边界，错误即信号

所有工具返回统一的 `ToolResult(status ∈ {ok, error, terminal})`，错误携带 `error_type`。
非法 JSON / 越界参数 / 缺失字段都不会让程序崩溃，而是变成可观测信息供其自我纠正。

### 5.5 配置校验集中在 `config.normalize()`

`normalize()` 负责：合并默认值、类型强制、按 `SPEC` 边界裁剪（回传 warnings）、
修正结构约束（`batch_size ≤ n_steps`、reward 键必须已知）。

### 5.6 双层记忆

- **短期**（`ShortTermMemory`）：会话内 trial 轨迹，渲染进上下文，限长。
- **长期**（`LongTermMemory`）：`agent_memory/longterm.json`（每次运行独立目录），
  存 `Lesson`，按任务名过滤去重，跨会话复用。

### 5.7 预算与上下文控制

三重预算（trial 数、墙钟秒、LLM 步数）+ 消息上限（`_cap_context`，默认 40 条）。
当前默认：**迭代次数不限**、**整体墙钟 8 小时**（`--wall`，0=不限）、
**per-trial 步数由 `--timesteps` 传入**（默认 200 000）。

---

## 6. Harness 隔离机制

`Harness/exec.py` 是 Agent 与 Env 的唯一交互通道：

- 接收工具名称 + 参数，从 `env_path` 动态 import 对应模块（`observation/metrics.py`
  或 `action/configure.py`），调用指定函数，返回结构化结果。
- Agent 不直接 `import` 任何 Env 代码，因此 **换 Env 不需改 Agent，换 Agent 不需改 Env**。

---

## 7. schedular.py 的职责

1. 创建时间戳 run_dir（`Runs/YYYYMMDD_HHMMSS/`）及子目录。
2. 首次运行时从模板复制 `Agents/PPOTuner/` 与 `Envs/Go2Locomotion-PPO/` 到 Task 目录下。
3. 修改两个 `config.json`，把 memory、logs、training_runs、observations 等路径重定向到 run_dir。
4. 实例化 `TuningAgent` 并注入 `goals`、`start_config`、`default_timesteps` 等任务参数。
5. 注册 `on_trial_done` 回调——每轮 trial 结束后调用 `CurveAnalyst` 分析曲线图。
6. 调用 `agent.run()`，ReAct 循环在 agent 内部运转，schedular 不干预。
7. 运行结束后写 `summary.json`（success、best_trial、metrics、usage、wall_seconds）。

## 8. 工具协议

| 工具 | 入参 | 返回（data 关键字段） |
|---|---|---|
| `run_training` | `config`, `timesteps`, `seed` | `run_id`, `summary{mean_return, fall_rate, mean_lin_vel_error, ...}`, `warnings` |
| `evaluate_policy` | `run_id`, `n_episodes`, `policy_mode` | `mean_return`, `fall_rate`, `mean_lin_vel_error`, `survival` |
| `get_metrics` | `run_id` | 学习曲线摘要（收敛趋势、末段回报） |
| `list_trials` | — | 已完成的 trial 列表（id + 关键指标） |
| `finish` | `success`, `reasoning` | 终结标记（status=terminal） |

## 9. 后训练可视化（`training/viz.py`）

每轮 trial 训练结束后自动产出可视化：

- **rollout 视频**：用 `mujoco.Renderer` 离屏渲染一次确定性 rollout，经 OpenCV 写成
  `rollout.mp4`；无 OpenCV 时退化为 `rollout.gif`。不引入额外依赖，headless 可用。
- **学习曲线**：`plot_training_curve()` 读 `metrics.csv`，用 matplotlib 画 episode return（灰）
  与 periodic greedy eval return（蓝），存 `curve.png`。

可视化是**尽力而为**的旁路——函数捕获所有异常后返回 `None`，不影响训练本身。
CLI 开关 `--no-viz` 可完全跳过。
