## 阶段 0 · 需求分析

**任务**：开发一个智能体，自动分析 Unitree Go2 机器狗在 MuJoCo 中的仿真训练结果，
自主调整参数直到达到预期效果；底座 `deepseek-flash`；须覆盖「需求分析 → 软件设计 →
编码实现 → 测试验证」，并完成 ≥1 轮「评测 → 分析 → 优化 → 再评测」。

**关键澄清**（与需求方确认）：
- 机器人 = **Unitree Go2**；调参层 = **RL 训练超参**。
- **设计重点是 Agent 本身**——源码、需求文档、架构文档都是针对 Agent 的；
  MuJoCo 仿真环境是支撑物，必须真实可跑，但不是设计重点。

**侦察（先摸清环境现实）**：
- Python 3.13.13（miniconda）；MuJoCo 3.10.0 已装、step 实测可跑。
- GitHub `git clone` 被重置，但 `raw.githubusercontent.com` / `api.github.com` 走 urllib 可用
  → Go2 模型可自动下载。
- 缺 `gymnasium` / `stable-baselines3` / `torch`，均可从 PyPI 装。
- DeepSeek key 有效，`deepseek-flash` 原生 function calling 可用。

**产出**：`doc/文档/需求文档.md`（场景、功能/非功能需求、验收标准），与 `doc/文档/架构文档.md` 的技术选型表。

## 阶段 1 · 仿真环境搭建（支撑物）

| 步骤 | 产物 | 说明 |
|---|---|---|
| 下载 Go2 模型 | `src/envs/fetch_go2.py` | 经 `api.github.com` 列目录、`raw.githubusercontent.com` 下载 `go2.xml`/`scene.xml` 及 16 个 `.obj`，带缓存 |
| Gymnasium 环境 | `src/envs/go2_env.py` | obs 42 维（base 角速度 3 + 投影重力 3 + 关节角 12 + 关节速 12 + 上一动作 12）；action 12 维关节位置目标；`frame_skip`、episode 长度、终止条件（过低/过倾）可配 |
| 可配置奖励 | `src/envs/reward.py` | 9 个奖励项加权，权重来自配置 |
| PPO 训练脚本 | `src/training/train_ppo.py` | SB3 PPO + DummyVecEnv + VecMonitor；输出 `config.json`/`metrics.csv`/`policy.zip`/`summary.json`；确定性评估（seed+12345） |

**问题与解决**：
- **torch 安装**：GPU 为 RTX 2080 Ti，但为简化与可复现，装 **CPU 版 torch**。
  PPO 小网络 + 短预算下 CPU 可接受（单轮 20k steps ≈ 90–150 s）。
- **确定性**：核验「同 config + 同 seed → 逐比特一致的 return」成立
  （196.4291 重跑一致），这是「可复现评测」这一非功能需求的基础。

## 阶段 2 · Agent 设计与编码（核心交付）

架构：`LLM（deepseek-flash）+ 工具层 + Harness 循环 + 记忆 + 反思`。

| 组件 | 文件 | 职责 |
|---|---|---|
| LLM 客户端 | `src/agent/llm.py` | OpenAI SDK 指向 `api.deepseek.com`；原生 function calling，失败时回退 JSON 解析；统一统计 token |
| 工具层 | `src/agent/tools.py` | `run_training` / `evaluate_policy` / `get_metrics` / `list_trials` / `finish`；**失败不抛异常，而是返回结构化 `ToolResult` 变成可观测信号** |
| 记忆 | `src/agent/memory.py` | 短期：本次会话 trial 轨迹；长期：`memory/longterm.json` 跨会话教训 |
| 反思 | `src/agent/reflection.py` | 每轮 trial 后用独立 LLM 调用诊断成因，产出一条可复用教训 |
| Harness 主循环 | `src/agent/agent.py` | ReAct 循环；trial / 墙钟 / LLM 步数三重预算；成功后落教训、终局写报告 |
| 提示 | `src/agent/prompts.py` | 系统提示 = 任务规格 + 搜索空间 + 诊断启发式；反思/终局模板 |

**技术选型**（详见架构文档）：**采用** ReAct（推理+行动交替，契合黑盒优化）、Tool Use（真实训练是外部耗时动作）、
Memory（避免重复试错）、Reflection（把一次实验变成一个先验）、轻量 Harness（预算约束）；
**不采用** RAG（无语料库，属过度设计）、Multi-Agent（单智能体+工具已足够，留作后续）。

**问题与解决**：
- **Benchmark 定型**：初版想直接学步态。实测发现——四足步态从零学习是**算力深度受限**的
  （真实 Go2 需 ~1e9 步，本地单 trial 仅 ~2e4 步）；20k 步预算下无论超参如何都趋于「站定」。
  遂**重构任务**为：**固定奖励函数 + 固定步数预算**，以 **mean_return** 为质量指标，
  让智能体在「PPO 超参 + PD/被控对象参数」空间做真正的黑盒优化，以**避开"训练崩溃悬崖"**体现能力。
- **防止作弊/保证公平**：在工具层加两道护栏——**奖励钉死**（Agent 对 `env.reward` 的修改被忽略）
  与**步数钳制**（`timesteps` 上限 = 任务预算）。这样 Agent 与基线在同一把尺子下比较。
- **任务标定**：`FIXED_REWARD` + 弱起点 `WEAK_START`（kp=30, action_scale=0.3, lr=3e-4）标定出
  弱起点 ≈148、调优后 ≈195–200 的区间，据此设三档阈值（`v1`=190、`hard`=192、`tight`=195+低摔倒率）。

## 阶段 3 · 测试验证

| 层次 | 手段 | 结果 |
|---|---|---|
| 单元 | mock 外部依赖，验证工具派发/边界/护栏 | 见测试结果文档 |
| 集成 | 真实 MuJoCo step + 脚本化 LLM | 通过 |
| 端到端 | 脚本化 LLM + stub 训练，跑通完整 ReAct 闭环（无网络） | 通过 |

**问题与解决**：
- 曾出现 `NameError: deepcopy not defined`（`runner.py` 中 `import copy` 被误删）
  → 加回模块级 `import copy` 并改用 `copy.deepcopy`。
- 端到端测试断言 `llm.calls[1]` 取错索引（那是反思调用而非下一步）
  → 改为遍历所有 `role=="tool"` 消息匹配。
- 曾怀疑训练不确定性（196/40/200 三档）→ 排查发现配置确实不同（`n_epochs`、`max_torque` 有差异），
  单独重跑证实训练确定性成立，非 bug。

**最终**：`python -m pytest` **58 passed**。

## 阶段 4 · 评测与优化（进阶要求）

### 4.1 第一轮评测（评测）

三个方法在同一任务 `go2_tune_v1` 上跑（固定种子）：

| method | 结果 | return | trials | wall_s | tokens |
|---|---|---|---|---|---|
| naive（弱起点跑一次） | **fail** | 147.7 | 1 | 92 | 0 |
| random（同预算随机搜索） | **fail** | 34.2 | 6 | 1377 | 0 |
| agent | **PASS** | 200.6 | 6 | 800 | 46636 |

只有 Agent 达标；random 6 个配置全踩「发散崖」，反证推理的价值。

### 4.2 分析（Analyze）

逐轮轨迹暴露两处**效率缺陷**：
1. Agent 在**第 2 轮**就已达 200.6（远超阈值），却把 6 轮预算烧光。
2. 每轮反思都给出同一条**不可执行**建议——"把 timesteps 提到 200000"，而步数预算是固定的。

### 4.3 优化（Optimize）

三处最小改动（不改任务定义、不动判分口径）：
| # | 改动 | 位置 |
|---|---|---|
| O1 | 达标早停信号：达标轮的 observation 追加 `[objective check] the goal is now MET ...` | `agent.py` |
| O2 | 反思约束：明令禁止"训得更久"，只推荐真正可调的参数 | `prompts.py` |
| O3 | 步数预算钳制（公平性护栏） | `tools.py` |

配套新增 6 个单元测试覆盖（信号注入、奖励钉死、步数钳制等）。

### 4.4 再评测（Re-evaluate）

| 指标 | R1 | R2 | 变化 |
|---|---|---|---|
| 成功 | ✅ | ✅ | 保持 |
| best_return | 200.6 | 198.4 | −1.1%（仍远超阈值） |
| 训练轮数 | 6 | **2** | **−67%** |
| 工具调用 | 7 | **3** | **−57%** |
| wall-clock | 800 s | **135.8 s** | **−83%** |
| 总 token | 46636 | **16638** | **−64%** |

**结论**：优化在**保持成功**的前提下把执行成本降到约 1/5，闭环有效。
详见 `doc/文档/评测报告.md`。

## 追加功能 · 训练结果可视化（后训练自动出一轮）

**动机**：训练只落盘 `metrics.csv` / `summary.json` 等数值产物，缺少直观的「策略跑起来是什么样」
与「学习曲线长什么样」，人工核对训练效果不便。

**实现**（`src/training/viz.py`，不引入任何新依赖）：

- **rollout 视频**：`mujoco.Renderer` 离屏渲染一次确定性 rollout，抽帧后用 OpenCV 写 `rollout.mp4`；
  无 OpenCV 时用 Pillow 退化为 `rollout.gif`。
- **学习曲线**：matplotlib（Agg）读 `metrics.csv` 画 episode return + greedy eval return，存 `curve.png`。
- 两个函数**捕获所有异常并返回 `None`**——可视化是旁路，绝不影响训练与指标。

**接线**：`train(visualize=...)` 增加开关 → 训练末尾产出视频与曲线并写入 `summary.visualization`；
经 `ToolContext.visualize` 从 `run_agent.py` CLI 透传（默认开）；`eval/runner.py` 批量评测**默认关**
（逐 trial 渲染会拖慢评测并占满磁盘）。训练脚本加 `--no-viz`。

**验证**：新增 `tests/test_viz.py`（5 例，含 1 slow 端到端渲染）；实测
`python -m src.training.train_ppo --out runs/_viztest --timesteps 3000` 产出
`rollout.mp4`（250 帧 / 30fps / 320×240 / 8.3s，解码非空白）与 `curve.png`。

## 关键取舍一览（供快速复盘）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 调参层 | RL 训练超参（PPO + PD 增益） | 需求方指定；且是该算力预算下真正可达的优化空间 |
| 奖励 | **固定**，不可被 Agent 修改 | 保证各 trial 的 return 可比、防止自评式作弊 |
| 步数预算 | **固定**，钳制 | 保证 Agent 与基线单轮算力一致 |
| torch | CPU 版 | 简化环境、保证可复现；短预算下够用 |
| 环境地位 | 支撑物，非设计重点 | 需求方明确；但做了确定性验证与集成测试 |
| 未采用 RAG / Multi-Agent | — | 该场景下属过度设计，已在架构文档说明 |
