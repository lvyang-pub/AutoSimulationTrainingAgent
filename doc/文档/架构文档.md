# 架构文档 — AutoSimulationTrainingAgent

## 1. 总体思路

智能体的任务是**黑盒配置优化**：每做一次实验（trial）= 用一组超参训练一个 PPO 策略，
观察指标后决定下一组配置。搜索空间维度不高但反馈噪声大、单次实验成本高，
因此需要「推理 + 行动」交替、把失败转成先验、并严格约束预算。

据此选择的技术与理由：

| 技术 | 是否采用 | 理由 |
|---|---|---|
| **ReAct** | 采用（核心） | 调参本质是「分析当前证据 → 决定下一个实验 → 观察结果」的闭环，Thought/Action/Observation 与之天然同构，比一次性规划更能吸收中间结果。 |
| **Tool Use** | 采用（核心） | 训练与评估是真实的、耗时的、可能失败的外部动作，必须以工具形式调用。用原生 function calling（DeepSeek 支持），失败时回退到 JSON 解析。 |
| **Memory** | 采用 | 短期记忆保存本次会话的 trial 轨迹（进上下文）；长期记忆跨会话持久化「教训」，避免重复试错——这是智能体相对随机搜索的核心增益来源。 |
| **Reflection** | 采用 | 每个 trial 后用独立 LLM 调用诊断「为何成功/失败」并抽取一条可复用教训，把一次实验的价值从「一个分数」提升为「一条先验」。 |
| **Planning + Harness** | 采用（轻量） | 不在前端做重规划，而是用一个受预算约束的 Harness 循环组织多轮探索（trial 数 / 墙钟 / LLM 步数三重上限）。 |
| **RAG** | 不采用 | 没有外部语料库；「知识」来自实验反馈本身（Memory 已覆盖），引入向量库属于过度设计。 |
| **Multi-Agent** | 未采用（作为对照讨论） | 单智能体 + 工具已能覆盖任务；多智能体收益主要在分工，而本任务的动作空间单一。可在后续以「独立 Critic」形式增量引入。 |

**一句话**：`deepseek-flash` 作为推理内核，套一个 **ReAct Harness**，通过 **工具层** 操作真实训练环境，
用 **双层记忆 + 反思** 累积经验，在 **预算** 内完成多轮自动调参。

## 3. 数据流（一次 trial）

1. LLM 输出 `run_training(config, timesteps, seed)`。
2. `config.normalize()` 对配置做**校验 + 越界裁剪 + 结构修正**，返回告警。
3. `train_ppo.train()` 启动 PPO 训练，落盘 `config.json / metrics.csv / policy.zip / summary.json`；
   训练结束后追加一次**后训练可视化**（见 §5.1），落盘 `rollout.mp4`（无 OpenCV 时退化为 `rollout.gif`）与 `curve.png`，
   路径写进 `summary.visualization`。
4. 工具把 `summary`（mean_return / fall_rate / mean_lin_vel_error / convergence_delta）回传为 Observation。
5. `reflection.reflect_on_trial()` 用一次独立 LLM 调用诊断该 trial，产出 `Lesson` 写入长期记忆。
6. 短期记忆追加一条 `TrialRecord`；上下文被 `_cap_context` 裁剪到上限。
7. Harness 检查预算与 `goal_met`；未达标则回到步骤 1，否则等待 `finish` 或预算耗尽。

## 4. 关键设计决策

### 4.1 成功判定与模型自评解耦
`goal_met()` 用 best trial 的客观指标判定成功。判据是**存在的键的子集**：任给
`mean_lin_vel_error_max` / `fall_rate_max` / `mean_return_min` 中出现的键都必须满足，
缺席的键忽略——于是任务可以只用「`mean_return_min`（+ 可选 `fall_rate_max`）」评分，
不需要速度误差项。同时记录模型的 `llm_finished_success`，评测只信客观判据，
避免「模型自称成功」被误计为成功。

### 4.1.1 固定奖励护栏（reward pinning）
若把奖励权重也交给智能体，它会倾向于**改写计分函数**而非真正调好超参——各 trial 的
return 便不可比，评分也失去意义。因此任务通过 `start_config.env.reward` 固定奖励，
`ToolContext.fixed_reward` 在 `run_training` 内**强制覆盖**智能体传入的 `env.reward`
并回一条告警。智能体只能在 PPO 超参与 PD/被控对象参数上优化。这把「调参」约束成了
一个**目标函数固定**的黑盒优化问题——也是评测能公平比较 agent / naive / random 的前提。

### 4.2 工具即边界，错误即信号
所有工具返回统一的 `ToolResult(status ∈ {ok, error, terminal})`，错误携带 `error_type`。
LLM 传出非法 JSON / 越界参数 / 缺失字段都不会让程序崩溃，而是变成一条可观测信息供其自我纠正——
这正是鲁棒性评测（故障注入、畸形输出）要检验的能力。

### 4.3 配置校验集中在 `config.normalize()`
LLM 是概率性的，直接信任其输出会污染训练。`normalize()` 负责：
- 合并默认值、类型强制；
- 按 `SPEC` 边界裁剪（并回传 `warnings`）；
- 修正结构约束（如奖励权重必须为已知项、`batch_size ≤ n_steps`）。

### 4.4 双层记忆
- **短期**（`ShortTermMemory`）：会话内 trial 轨迹，渲染进上下文，限长。
- **长期**（`LongTermMemory`）：`memory/longterm.json`，存 `Lesson`，按任务名过滤去重，跨会话复用。
  反思是把长期记忆内容「写厚」的唯一入口，保证记忆不是日志而是可迁移的先验。

### 4.5 预算与上下文控制
三重预算（trial 数、墙钟秒、LLM 步数）+ 消息上限（`_cap_context`，默认 40 条）共同保证
token 与时间可预测——这是「执行效率」指标可控的前提。

## 5. 工具协议

| 工具 | 入参 | 返回（data 关键字段） |
|---|---|---|
| `run_training` | `config`, `timesteps`, `seed` | `run_id`, `summary{mean_return, fall_rate, mean_lin_vel_error, ...}`, `warnings` |
| `evaluate_policy` | `run_id`, `n_episodes`, `policy_mode` | `mean_return`, `fall_rate`, `mean_lin_vel_error`, `survival` |
| `get_metrics` | `run_id` | 学习曲线摘要（收敛趋势、末段回报） |
| `list_trials` | — | 已完成的 trial 列表（id + 关键指标） |
| `finish` | `success`, `reasoning` | 终结标记（status=terminal） |

### 5.1 后训练可视化（`training/viz.py`）

每轮 trial 训练结束后自动产出一份结果可视化，方便人工核对训练效果：

- **rollout 视频**：用 `mujoco.Renderer` **离屏渲染**一次确定性 rollout（`policy.predict(deterministic=True)`），
  按 `frame_skip_render` 抽帧，经 OpenCV 写成 `rollout.mp4`；若环境没有 OpenCV，则用 Pillow 退化为
  `rollout.gif`——**不引入任何新依赖**，headless 也可用。
- **学习曲线**：`plot_training_curve()` 读 `metrics.csv`，用 matplotlib（Agg 后端）画 episode return（灰）
  与 periodic greedy eval return（蓝）随 timesteps 的曲线，存 `curve.png`。

设计约束：可视化是**尽力而为**的旁路——两个函数都捕获所有异常并返回 `None`（而非抛出），
渲染失败绝不影响训练本身与 `summary` 中的指标。开关由 `train(visualize=...)` 控制，
经 `ToolContext.visualize` 从 CLI 透传；agent / 训练脚本默认开，**批量评测默认关**
（`eval/runner.py` 传 `visualize=False`），以免每次 trial 都渲染拖慢评测并占满磁盘。

## 6. 评测架构

- `eval/tasks.py`：固定任务集。每个任务 = 固定奖励 + **故意较弱的起始配置**（`WEAK_START`，
  低 PD 增益 / 小 action_scale）+ `mean_return` 阈值（部分任务加 `fall_rate` 阈值）+ 预算 + 固定种子。
  阈值取自实测标定：弱起配置 ≈150，调好的配置 ≈195–197，故 `mean_return_min` 取 190–195。
- `eval/runner.py`：三种方法同预算对照（三者都固定奖励、同起始前提）——
  - `agent`：本智能体（ReAct + 记忆 + 反思）；
  - `naive`：任务给定的**弱起始配置**单次训练（不调参）；
  - `random`：同等 trial 预算的随机搜索（只随机超参/PD 参数，不搜奖励权重）。
- `eval/metrics.py` + `report.py`：汇总成功率、结果质量、工具效率、执行效率、鲁棒性，渲染 Markdown，
  并支持与上一轮 `outcomes.json` 对比，支撑「评测→分析→优化→再评测」。
