# 需求文档 — AutoSimulationTrainingAgent

## 1. 背景与目标

在机器人仿真训练中，强化学习（RL）策略能否收敛，高度依赖训练超参与奖励权重的组合。
人工调参需要反复训练、观察指标、凭经验调整，迭代慢且难以复用经验。

本项目开发一个**智能体软件**：它能够自动分析 Unitree Go2 机器狗在 MuJoCo 中的仿真训练结果，
自主调整 **训练超参（PPO 超参 + PD/被控对象参数）**，直到短程训练达到尽可能高的回报
（或耗尽预算）。

> **任务定型的依据（实测）**：四足步态从零学习是**算力深度受限**的——真实 Go2 的 RL 步态训练
> 通常需要 ~1e9 步环境交互，而本项目单机 CPU 单 trial 仅 ~2e4 步。实测在 20k 步预算下，
> 无论超参如何，机器狗都趋向「站定不动」（前向速度≈0），步态学习不是该预算下可达的目标。
> 因此**不做奖励权重的自评式作弊**：任务**固定奖励函数**（保证各 trial 的 return 可直接比较），
> 让智能体在「PPO 超参 + PD/被控对象参数」空间上做真正的黑盒优化，以 **mean_return** 为质量指标，
> 并以避开「训练崩溃悬崖」（lr 过大、kp 过刚、action_scale 过大）作为能力的体现。

**核心交付是智能体的设计**（源码、需求文档、架构文档、测试与评测报告）。MuJoCo 仿真训练环境是支撑物，
必须真实可跑，但它本身不是设计重点。

## 2. 角色与范围

- 角色：研发人员，完成「需求分析 → 软件设计 → 编码实现 → 测试验证」完整过程。
- 底座模型：`deepseek-flash`（OpenAI 兼容接口，支持 function calling）。
- 机器人：Unitree Go2（MuJoCo Menagerie 官方 MJCF，12 个力矩电机，自由基座）。

## 3. 术语

| 术语 | 含义 |
|---|---|
| Trial | 一次完整的 PPO 训练（一组超参配置 + 固定训练步数），产生一个可评估的策略 |
| Goal | 任务成功判据（主要看 `mean_return` 阈值，部分任务附加 `fall_rate` 阈值） |
| Session | 智能体针对一个任务的一次运行，包含若干 trial，受试次/时间预算约束 |
| Fixed reward | 任务固定的奖励函数，智能体不得修改；使各 trial 的 return 可直接比较 |

## 4. 功能需求

### FR1 训练环境（支撑物）
- FR1.1 自动获取 Go2 模型文件，无需人工干预。
- FR1.2 提供 Gymnasium 环境：可配置观测、动作、控制频率、回合长度、终止条件。
- FR1.3 奖励函数由配置化的加权项组成；**本任务中由任务固定**（智能体不得改动，工具层强制），
  以保证跨 trial 的回报可比。
- FR1.4 一次训练输出结构化产物：`config.json`、`metrics.csv`、`policy.zip`、`summary.json`。

### FR2 智能体核心
- FR2.1 **工具使用（Tool Use）**：提供 `run_training`、`evaluate_policy`、`get_metrics`、`list_trials`、`finish` 五个工具。
- FR2.2 **ReAct 循环**：智能体交替「推理 → 选择并调用一个工具 → 观察结果」，直至达标或预算耗尽。
- FR2.3 **配置校验**：工具对 LLM 传入的配置做类型校验、范围裁剪与结构约束修正，并回传告警。
- FR2.4 **记忆**：短期记忆保存本次 session 的 trial 轨迹；长期记忆跨 session 持久化「教训」，供后续复用。
- FR2.5 **反思（Reflection）**：每个 trial 结束后，独立 LLM 调用诊断成败原因并生成一条可复用教训写入长期记忆。
- FR2.6 **预算控制**：受最大 trial 数、墙钟时间、最大 LLM 步数三重约束。
- FR2.7 **目标判定**：成功由客观指标判定（不依赖模型自评），同时记录模型的自我声明以便对照。
- FR2.8 **奖励固定护栏**：工具层强制用任务固定的 `env.reward` 覆盖智能体传入的奖励权重，
  并回告警；智能体只能在超参/PD 参数上优化。

### FR3 评测与优化
- FR3.1 提供若干**固定、可复现**（固定种子）的调参任务。
- FR3.2 支持多种方法对照：`agent`（本智能体）、`naive`（任务给定的弱起始配置单次训练）、
  `random`（同等预算的随机搜索，且同样固定奖励、不搜索奖励权重）。
- FR3.3 统计指标：任务成功率、结果质量、工具使用效率、执行效率（时间/Token）、鲁棒性。
- FR3.4 支持**故障注入**（令某次 `run_training` 失败）以度量智能体的恢复能力。
- FR3.5 生成 Markdown 评测报告，并支持与上一轮评测对比，以完成「评测 → 分析 → 优化 → 再评测」。

## 5. 非功能需求

- NFR1 **可复现**：固定种子下，同一任务的评测结果可复现。
- NFR2 **鲁棒性**：LLM 输出不规范、工具失败、参数越界时，智能体不崩溃，能将错误作为可观测信号继续推理。
- NFR3 **可观测**：全程记录 token 消耗、工具调用次数与成功率、每 trial 指标、停止原因。
- NFR4 **可移植**：不依赖 GPU（PPO 小网络 + 短预算在 CPU 上可运行）；不依赖被墙的 `git clone`。
- NFR5 **可扩展**：新增任务/工具/指标不改动核心循环。

## 6. 验收标准

1. `python scripts/setup_env.py` 能自动下载模型并通过环境冒烟测试。
2. `python scripts/run_agent.py` 能跑通一个 session，产生多轮 trial、反思与长期记忆写入、最终报告。
3. `python scripts/run_eval.py` 能输出指标表、基线对比，且可重复运行结果一致。
4. 至少完成 1 轮「评测 → 分析 → 优化 → 再评测」，并在评测报告中体现前后对比。
5. 交付：源码、需求文档、架构文档、测试报告、评测报告、演示脚本。

## 7. 约束与假设

- 网络：GitHub `git clone` 被重置，采用 `raw.githubusercontent.com` + `api.github.com` 逐文件获取。
- 计算：单机 CPU 训练，单 trial 目标 1–3 分钟，以支撑多轮搜索（实测 20k 步 ≈ 140s）。
- 失败模式预期：四足步态在 ~2e4 步预算下不可学（见 §1 说明），**智能体的价值体现在
  在固定奖励下系统性地找到高回报、避开崩溃悬崖的超参，并复用经验**，而非保证学会步态。
